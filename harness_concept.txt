# 하네스 엔지니어링 핵심 지식 가이드 (Harness Engineering)

본 지식은 미첼 하시모토(Mitchell Hashimoto, 2026년 2월 제창), 오픈AI, 앤스로픽, 랭체인 팀의 실무 레슨런을 바탕으로 작성되었습니다. 에이전트의 성능을 결정하는 것은 모델의 지능이 아니라 이를 제어하는 시스템(하네스)입니다.

## 1. 하네스의 3대 기둥
1) 컨텍스트 파일 (harness.md / agent.md)
   - 백과사전식 1,000페이지 설명서가 아니라 '60줄 이하의 핵심 지도'로 유지한다.
   - 프로젝트 구조, 빌드/테스트 명령어, 절대 하지 말아야 할 규칙만 보편적으로 정의한다.
   - 처음부터 완벽하게 짜지 않으며, 에이전트가 '실패할 때마다 규칙을 한 줄씩 추가'하며 진화시킨다.
2) 자동 강제 시스템 (Automated Enforcement)
   - 프롬프트는 '부탁'이지만 하네스는 '강제'이다. 
   - 린터, 프리커밋 훅(Pre-commit Hook) 등을 기계적으로 결합하여 규칙 위반 시 저장/커밋 자체가 불가능한 구조를 만든다.
   - 자동 교정 루프: 에러가 나면 에이전트가 스스로 코드를 수정하게 만든다.
   - 원칙: 성공은 조용히(출력 생략), 실패만 시끄럽게(에러만 상세 보고) 하여 토큰을 절약한다.
3) 가비지 컬렉션 (Garbage Collection)
   - 프로젝트 내의 나쁜 코드 패턴이나 낡은 규칙을 주기적으로 청소하여 에이전트가 악성 패턴을 학습·복제하는 것을 원천 차단한다.

## 2. 긴 작업(Long-running Task) 수행 원칙 (앤스로픽 가이드)
- 컨텍스트 부패(Context Rot): 대화가 길어지면 앞 내용을 잊거나 조기 종료해버리는 현상.
- 해결책으로 2개의 추적 파일을 운영한다.
  ① 진행 일지(Progress Log): 오늘 무엇을 했고, 어디까지 되었으며, 다음에 무엇을 할지 기록 (인수인계 문서 역할)
  ② 기능 목록(Feature List): 구현해야 할 기능을 나열하고 완료 여부를 True/False로 마킹.
- 컨텍스트 잔여량이 40% 이하일 때 가장 이상적으로 작동하며, 세션이 무거워지면 메인 세션을 보존하기 위해 '포크(Fork) 기능'을 활용해 복제본에서 세부 작업을 수행한 뒤 결과만 메인으로 가져온다.
