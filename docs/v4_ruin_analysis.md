# v4.0 포트폴리오 Ruin 원인 서면 (Phase G)

> **브랜치 정책:** `main` 병합·PR 없음. v4.0 검증 브랜치에서 SSOT(`config/settings.yaml` `v4_0.*`)만 조정·재실행한다.  
> **근거 자료:** Phase B `outputs/v4_audit_sizing.md` · Phase C `outputs/v4_parity_report.md` · Phase D/G `run_v4_portfolio.py` 성적표.

## 1. 요약 (Executive Summary)

전 종목 포트폴리오 백테스트(2023-01-01 ~ 2026-05-31)에서 **승률은 60%대이나 누적 수익률은 -97% ~ -99%** 구간에 머문다. 이는 Harness 단일종목 엔진 버그가 아니라, **다종목 자금 경쟁 + 손익비(PF&lt;1) + 포지션 규모**가 겹친 **계좌 Ruin(자본 소멸)** 현상으로 해석한다.

Phase G 목표는 main 병합이 아니라:

1. Ruin 메커니즘을 **서면으로 고정** (본 문서)
2. `v4_0.strategy` 하이퍼파라미터를 **YAML SSOT로 튜닝** (`run_v4_tune.py` 성적표)
3. PF≥1·MDD 완화·최종 equity 개선 여부를 **수치로 판단**

## 2. Ruin이란 무엇인가 (본 프로젝트 정의)

| 용어 | 정의 |
|------|------|
| **Ruin** | 초기 자본(3,000만 원) 대비 최종 equity가 구조적으로 붕괴하고, MDD가 -90%대에 수렴하는 상태 |
| **PF (Profit Factor)** | 총 이익 ÷ 총 손실. **1.0 미만**이면 승률이 높아도 장기적으로 자본이 감소 |
| **Phase G 모드** | 슬롯당 **단리 고정 투자금**(`fixed_invest_amount`) + 눌림·손절·익절·당일 배분 상한 |

단일종목 `smart_money_cascade`는 회차별 비율만 기록하고 **실제 현금 배분이 없다**. 포트폴리오는 **현금·슬롯·동시 보유**가 있으므로 동일 신호라도 **체결 순서·Pass·연쇄 시퀀스**가 달라진다(Phase C LG 3회차 사례).

## 3. 1차 원인 (증거 기반)

### 3.1 손익비 구조 (PF &lt; 1)

- Phase B: 승률 **약 67%**, **PF 약 0.36** — 평균 손실 &gt; 평균 이익.
- Phase G 기본 파라미터(눌림 -3%, 익절 +3.5%, 손절 -5%): **PF 약 0.57**, 최종 equity **약 63만 원(-97.9%)** (`progress.md` 2026-06-01 기록).
- **시사:** 진입 빈도·승률만으로는 회복 불가. **손절 폭·익절 폭·눌림 깊이** 조합이 PF를 1.0 이상으로 끌어올릴 수 있는지 튜닝 대상이다.

### 3.2 동시 노출·예수금 소진

- Phase B-1d: **1회차 동시 3종목** 매수일 다수. 당일 현금 투입/총자산 **최대 50%** (3슬롯 × 회차별 alloc).
- `max_daily_cash_deploy_ratio`(기본 0.45)는 Phase D에서 도입했으나, **단리 1,000만 원 × 3슬롯**이면 equity 축소 후에도 **절대 손실액**이 커질 수 있다.
- **시사:** `fixed_invest_amount` **하향**(예: 300만 원) 및 `max_daily_cash_deploy_ratio` **축소**로 연속 손절 시 생존 시간을 늘린다.

### 3.3 유령 tracked (기준봉 지연 진입)

- Phase B-2: 기준봉 대비 **30영업일 초과** 진입 BUY **16.3%**, 최대 지연 **837일**.
- D-2에서 `max_track_days: 30` 만료를 반영했으나, **0~5일 지연 구간**이 실현 손실 합계의 최대(-1,887만 원 수준).
- **시사:** 만료만으로 Ruin이 해소되지 않음. **진입 직후 구간의 손익비**가 더 중요.

### 3.4 다종목 슬롯 경쟁 (엔진 불일치 vs 정합)

- Phase C: LG전자 **1~2회차 패리티 일치**, 3회차는 포트가 단일 대비 **다른 일자 청산** (슬롯·현금 경쟁).
- **시사:** “엔진 버그”보다 **포트폴리오 제약 하의 전략 한계**에 가깝다. 패리티는 **시퀀스 검증**용, Ruin 해결은 **사이징·손익 파라미터** 쪽이다.

### 3.5 Phase D 이전: 총자산 비례 재투자

- D 이전: `slot_budget = total_equity / max_slots` 동적 축소·확대 → equity 하락 시에도 **상대적 노출**이 남아 Ruin 가속.
- Phase G **단리 고정**은 이 경로를 차단하나, **절대 투자금이 크면** 여전히 급락 가능.

## 4. 튜닝 레버 (SSOT: `config/settings.yaml` → `v4_0.strategy`)

| 키 | 역할 | Ruin 완화 방향 | PF 개선 방향 |
|----|------|----------------|--------------|
| `fixed_invest_amount` | 슬롯당 단리 투자금(원) | **↓** (예: 300만) — 1회 손실 절대액 축소 | 과소 시 수익 기여 감소 → 균형 필요 |
| `max_daily_cash_deploy_ratio` | 당일 현금 배분 상한 | **↓** (예: 0.15~0.25) — 동시 진입·연속 손절 버팀 | 기회 비용 증가 |
| `nuliim_ratio` | 기준봉 종가 대비 눌림 깊이 | 깊게(↑%) — 진입 보수화 | 얕게(↓%) — 체결↑·노이즈↑ |
| `stop_loss_ratio` | 하드 손절 | **↓** — 손실 폭 축소(손절 빈도↑) | **↑** — 완화(대형 손실 허용) |
| `target_profit_ratio` | 고정 익절 | **↑** — 이익 leg 확대 | **↓** — 빠른 익절·승률↑ PF↓ 가능 |

**주의:** Harness `main`/GUI `simulator.py`와 **무관**. `run_v4_portfolio.py` · `run_v4_tune.py`만 `v4_0`를 읽는다.

## 5. 권장 튜닝 절차 (현재 브랜치)

1. **기준선:** `python run_v4_portfolio.py` — 현재 YAML 그대로 성적표 저장.
2. **시나리오 스윕:** `python run_v4_tune.py` → `outputs/v4_tune_report.md` · `outputs/v4_tune_results.csv`
3. **축소 그리드(빠른 확인):** `python run_v4_tune.py --quick`
4. **채택 후보 선정:** PF≥1, MDD·최종 equity, SELL 건수를 함께 보고 `settings.yaml`에 **수동 반영** (자동 main 병합 없음).
5. **패리티 회귀(선택):** 파라미터 확정 후 `python run_v4_parity.py` — LG 시퀀스 drift 여부만 확인.
