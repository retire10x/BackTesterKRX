# 작업지시서: v6.0 데이터베이스 구축 및 웹 대시보드 전환 로드맵

> **핵심 원칙:** v5.5.2 황금 수식 엔진 코어는 **단 한 줄도 수정하지 않는다.**  
> DB(영구 저장소)와 Web(화면)만 외곽에 안전하게 이어 붙인다.  
> **브랜치:** `v5.0` 위에 점진 적용 (엔진 동결 유지)  
> **관련 문서:** `docs/live_SOP_guide.md` · `docs/live_daily_manual.md` · `harness.md`

---

## 1. 왜 v6.0인가

| 현재 (v5.5.2) | 한계 | v6.0 목표 |
|---------------|------|-----------|
| `config/live_positions.json` | 장부가 파일 하나. 웹·통계·복기에 불편 | SQLite 영구 저장 |
| 청산 로그 | 터미널 로그만 남음. 주말 복기·수익률 집계 불가 | `trading_history` 누적 |
| 자산 추이 | 매일 스냅샷 없음. 그래프 불가 | `daily_snapshots` 일별 박제 |
| 모니터링 | PowerShell 터미널만 | 브라우저 대시보드 |

**신뢰 원칙:** 매매 판단(진입·청산 수학)은 이미 검증된 `portfolio_manager_v5` / `live_signals` 경로를 그대로 쓴다. 바꾸는 것은 **기억하는 방법**과 **보는 방법**뿐이다.

## 5. DB 선정: SQLite3

| 항목 | 결정 |
|------|------|
| 엔진 | **SQLite3** (`sqlite3` — Python 표준 라이브러리) |
| 파일 위치 | `data/live_trading.db` (권장) |
| 설치 | **추가 설치 없음** — venv·PC 공통 |
| 동시성 | 마스터 봇 1프로세스 + 웹 읽기 전용 → WAL 모드로 충분 |

**WAL 모드 권장:** 장중 0.5초 쓰기와 웹 읽기가 겹쳐도 잠금 충돌을 줄인다.

```sql
PRAGMA journal_mode=WAL;
PRAGMA foreign_keys=ON;
```

## 6. 테이블 스키마 (1단계 설계)

### 6.1 `holding_positions` — 현재 보유 종목 (실시간 장부)

**역할:** `config/live_positions.json` 대체. 장중 튕김 후에도 포지션 복구.

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `symbol` | TEXT | **PK** | 종목코드 6자리 (`274090`) |
| `name` | TEXT | NOT NULL DEFAULT '' | 종목명 (유니버스·KIS 시세에서 보강) |
| `entry_date` | TEXT | NOT NULL | 진입 일자 `YYYYMMDD` |
| `entry_price` | REAL | NOT NULL | 평단가 |
| `quantity` | INTEGER | NOT NULL | 보유 수량 (주) |
| `hold_days` | INTEGER | NOT NULL DEFAULT 0 | 보유 영업일 (타임스탑용) |
| `updated_at` | TEXT | NOT NULL | ISO8601 KST 갱신 시각 |

```sql
CREATE TABLE IF NOT EXISTS holding_positions (
    symbol       TEXT PRIMARY KEY,
    name         TEXT NOT NULL DEFAULT '',
    entry_date   TEXT NOT NULL,
    entry_price  REAL NOT NULL CHECK (entry_price > 0),
    quantity     INTEGER NOT NULL CHECK (quantity > 0),
    hold_days    INTEGER NOT NULL DEFAULT 0 CHECK (hold_days >= 0),
    updated_at   TEXT NOT NULL
);
```

#### 현재 JSON과의 매핑

| `live_positions.json` | `holding_positions` | 비고 |
|-----------------------|---------------------|------|
| `positions[].code` | `symbol` | `zfill(6)` 유지 |
| *(없음)* | `name` | **신규** — 스캐너 `live_today_universe.meta.json` 에서 조회 |
| `positions[].entry_date` | `entry_date` | 현재 `YYYY-MM-DD` → DB는 `YYYYMMDD` 통일 |
| `positions[].entry_price` | `entry_price` | 동일 |
| `positions[].qty` | `quantity` | 컬럼명만 변경 |
| `positions[].hold_days` | `hold_days` | 동일 |
| `updated_at` (루트) | 행별 `updated_at` | 행 단위 갱신으로 세분화 |

### 6.2 `trading_history` — 영구 매매 복기 장부

**역할:** 익절·손절·타임스탑 청산 기록 누적. 주말 통계·대시보드 거래 내역의 원천.

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `id` | INTEGER | **PK** AUTOINCREMENT | 거래 일련번호 |
| `symbol` | TEXT | NOT NULL | 종목코드 |
| `name` | TEXT | NOT NULL DEFAULT '' | 종목명 |
| `entry_date` | TEXT | NOT NULL | 매수 일자 |
| `entry_price` | REAL | NOT NULL | 매수 가격 |
| `exit_date` | TEXT | NOT NULL | 매도 일자 |
| `exit_price` | REAL | NOT NULL | 매도 가격 |
| `quantity` | INTEGER | NOT NULL | 매도 수량 |
| `profit_rate` | REAL | NOT NULL | 확정 수익률 (소수, 예: `0.08` = +8%) |
| `reason` | TEXT | NOT NULL | 청산 사유 코드 |

```sql
CREATE TABLE IF NOT EXISTS trading_history (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    symbol       TEXT NOT NULL,
    name         TEXT NOT NULL DEFAULT '',
    entry_date   TEXT NOT NULL,
    entry_price  REAL NOT NULL,
    exit_date    TEXT NOT NULL,
    exit_price   REAL NOT NULL,
    quantity     INTEGER NOT NULL,
    profit_rate  REAL NOT NULL,
    reason       TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_trading_history_exit_date ON trading_history(exit_date);
CREATE INDEX IF NOT EXISTS idx_trading_history_symbol ON trading_history(symbol);
```

#### `reason` 코드 — v5.5.2 엔진과 1:1 대응

| `reason` 값 | 의미 | 발생 위치 |
|-------------|------|-----------|
| `TAKE_PROFIT` | +8% 익절 | `live_signals.evaluate_hit_and_run_exit` |
| `STOP_LOSS` | -3% 손절 | 동일 |
| `TIME_STOP` | 4영업일 타임스탑 | 동일 |
| `TIME_STOP_EOD` | 장마감 강제 청산 | `live_engine.monitor_market_realtime` |

#### `profit_rate` 계산식 (비용 반영 권장)

```
profit_rate = (exit_price * quantity * (1 - sell_cost_ratio))
            / (entry_price * quantity * (1 + buy_cost_ratio))
            - 1.0
```

- `buy_cost_ratio` / `sell_cost_ratio` 는 `live_settings.yaml` `account` 블록과 동일.
- Dry-Run 시에도 동일 공식으로 기록 → 백테스트·실전 비교 일관성 유지.

#### 현재 시스템 갭

- **v5.5.2는 청산 시 JSON에서 행을 삭제만 하고 영구 기록을 남기지 않는다.**
- 2단계에서 `monitor_market_realtime` 청산 직후 `insert_trading_history()` 호출을 **외곽 훅**으로 추가한다. `evaluate_hit_and_run_exit` 본문은 수정하지 않는다.

### 6.3 `daily_snapshots` — 일별 자산 성장 곡선

**역할:** 장마감 후 총자산 박제. 웹 대시보드 우상향 자산 그래프 원천.

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `base_date` | TEXT | **PK** | 기준 일자 `YYYYMMDD` |
| `available_cash` | REAL | NOT NULL | 당일 마감 예수금 |
| `total_evaluation` | REAL | NOT NULL | 당일 마감 주식 평가금액 |
| `total_asset` | REAL | NOT NULL | 총자산 (예수금 + 평가) |

```sql
CREATE TABLE IF NOT EXISTS daily_snapshots (
    base_date          TEXT PRIMARY KEY,
    available_cash     REAL NOT NULL,
    total_evaluation   REAL NOT NULL,
    total_asset        REAL NOT NULL CHECK (total_asset >= 0)
);
```

#### 데이터 소스

| 컬럼 | KIS / 게이트웨이 매핑 |
|------|----------------------|
| `available_cash` | `AccountSnapshot.cash` (`ord_psbl_cash` 등) |
| `total_evaluation` | `AccountSnapshot.stock_eval` |
| `total_asset` | `AccountSnapshot.total_equity` |

#### 기록 시점 (권장)

- **15:30 이후** 마스터 `tick()` 에서 당일 1회 (`live_master_state` 와 유사한 `snapshot_date` 플래그).
- Dry-Run: `snapshot_after_local_fill` 기반 로컬 추정치로 기록 가능 (실전 전 검증용).

## 7. `live_db.py` 모듈 설계 (2단계 예고)

파일: `src/live/live_db.py`

### 7.1 공개 API (엔진이 호출할 최소 표면)

```python
# 포지션 — live_engine._load/_save_positions 대체
def load_holding_positions() -> list[LivePosition]: ...
def save_holding_positions(positions: list[LivePosition]) -> None: ...
def upsert_holding_position(pos: LivePosition, *, name: str = "") -> None: ...
def delete_holding_position(symbol: str) -> None: ...

# 청산 기록 — monitor_market_realtime 청산 직후
def insert_trading_history(...) -> int: ...

# 일별 스냅샷 — 장마감 1회
def upsert_daily_snapshot(base_date: str, cash: float, eval: float, total: float) -> None: ...

# 1회성 마이그레이션
def migrate_from_json(positions_json_path: str) -> int: ...
def init_schema(db_path: str | None = None) -> None: ...
```

### 7.2 `LivePosition` 호환

- `src/live/live_account.py` 의 `LivePosition` dataclass를 **그대로** 사용한다.
- DB 컬럼명(`symbol`, `quantity`)과 코드 필드명(`code`, `qty`) 변환은 `live_db.py` 내부에서만 처리 → **엔진 코어 타입 변경 없음**.

### 7.3 JSON 폴백 정책 (전환기)

| 기간 | 정책 |
|------|------|
| 2단계 초반 | DB 비어 있으면 `live_positions.json` 자동 마이그레이션 1회 |
| 2단계 완료 후 | JSON 쓰기 중단. JSON은 `.gitignore` 유지 (백업용 잔재) |
| 롤백 | `LIVE_USE_JSON_LEDGER=1` 환경변수로 JSON 경로 복귀 (비상용) |

## 8. 웹 대시보드 설계 (3·4단계 예고)

### 8.1 백엔드 후보

| 프레임워크 | 장점 | 단점 |
|------------|------|------|
| **FastAPI** | 타입 힌트·자동 OpenAPI 문서 | 의존성 1개 추가 |
| **Flask** | 가볍고 익숙함 | async 미약 |

**권장:** FastAPI — `/docs` 로 API 자동 문서화, 대시보드 확장에 유리.

### 8.2 REST 엔드포인트 초안

| Method | Path | 응답 |
|--------|------|------|
| GET | `/api/positions` | `holding_positions` 전체 + 미실현 손익(시세 조회) |
| GET | `/api/history` | `trading_history` (쿼리: `?from=&to=`) |
| GET | `/api/snapshots` | `daily_snapshots` (차트용 시계열) |
| GET | `/api/summary` | 승률·누적 수익·오늘 PnL 요약 |

### 8.3 프론트엔드

- **HTML + Tailwind CSS** (CDN) — 빌드 도구 없이 단일 페이지.
- 차트: Chart.js 또는 Lightweight Charts.
- 갱신: 5~10초 폴링 (WebSocket는 v6.1 이후).

### 8.4 프로세스 배치

```
[run_live_bot.py]  ──쓰기──►  data/live_trading.db
                                    ▲
[run_live_dashboard.py]  ──읽기──┘
```

- 마스터 봇과 대시보드는 **별도 프로세스**. DB만 공유.
- 대시보드는 매매 로직에 **절대 개입하지 않는다**.
