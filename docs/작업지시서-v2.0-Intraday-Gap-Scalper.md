# 국장 대형주 시가 돌파형 단타 백테스트 엔진 v2.0 (Intraday Gap Scalper) 작업지시서

이 문서는 일봉(OHLCV) 데이터 기반에서 “Look-ahead Bias”를 최소화하며 동작하도록 설계된, **시가 돌파형 당일 청산(Day-Trading)** 백테스트 엔진 구현을 위한 단계별 요구사항입니다.

프로젝트명: 국장 대형주 시가 돌파형 단타 백테스트 엔진 빌드 (v2.0)  
담당 마일스톤: 브랜치 `v2.0` (Intraday Gap Scalper)

---

## 1. 입력/출력 개요

### 1.1 입력(데이터)
- KOSPI 종목 Universe
- 일봉 OHLCV (`시가, 고가, 저가, 종가, 거래량`)

### 1.2 출력(산출물)
- `all_trades` 기반 거래 로그(매매 유형 + 수익률 return)
- 터미널 출력 전용 성과표(아래 `print_dashboard` UI 템플릿 준수)

## 2. 단계별 개발 가이드라인

### [1단계] 데이터 수집 및 전처리 모듈 (Data Loader)

**목적:** 백테스트에 필요한 KOSPI 일봉(OHLCV)을 안정적으로 확보합니다.

**요구사항**
1. `pykrx.stock.get_market_ticker_list()`로 특정 시점의 KOSPI Universe를 동적으로 확보합니다.
2. `pykrx.stock.get_market_ohlcv_by_date()`로 지정된 기간의 일봉 OHLCV를 수집합니다.
3. 데이터 검증:
   - 거래정지 등으로 데이터가 부족한 종목은 `len(df) < 2`일 때 예외 처리하여 **제외**합니다.

**구현 주의**
- `pykrx`는 `KRX_ID/KRX_PW` 로그인 정보가 필요할 수 있습니다. 현재 구현은 로컬 환경에서 pykrx 조회가 실패하면 기존 프로젝트의 `FinanceDataReader` 기반 데이터로 폴백하도록 되어 있습니다(전처리 로직은 동일).

**예상 산출물**
- `tickers: list[str]`
- `df: pandas.DataFrame` (index는 날짜, 컬럼은 `시가/고가/저가/종가/거래량`)

---

### [2단계] v2.0 주도주 진입 필터 모듈 (Signal Generator)

**목적:** 아침 시장에서 “갭 + 거래량 회전”이 동시에 폭발하는 당일 주도주를 포착해 진입 조건을 만듭니다.

**요구사항**
1. 일별 루프를 순회하며 전일/당일을 비교 연산합니다. (인덱스는 `i-1` → `i` 방향으로 이동)
2. 지표 정의:
   - 시가 갭 비율(%)  
     `gap_pct = ((당일 시가 - 전일 종가) / 전일 종가) * 100`
   - 거래량 회전 비율(%)  
     **(보정안)** `vol_ratio = (전일 거래량 / 전전일 거래량) * 100`
3. 진입 시그널 조건(당일 시가 매수 체결 확정):
   - `(2.0 <= gap_pct < 5.0)` AND `(vol_ratio >= 150.0)`
4. 진입 시점:
   - 조건 만족 시 **해당 봉의 시가(Open)** 를 매수 체결가 기준으로 확정합니다.

**주의(정합성)**
- 본 v2.0에서는 `vol_ratio`를 **전일/전전일 거래량**으로 정의합니다.  
  따라서 “전일 이미 거래량이 폭발한 주도주 후보”가 **당일 +2%~+5% 갭**을 띄울 때, 일봉 기반에서도 체결 시점 판정의 왜곡을 최소화합니다.

---

### [3단계] 실전 매매 비용 및 청산 시뮬레이터 (Execution Engine)

**목적:** 일봉 데이터에서 봉 내부 시간 순서를 알 수 없는 한계를 인정하고, **Bias-Free 플랫 구조**로 당일 매매를 시뮬레이션합니다.

**구현 규격 (확정)**
- 봉 내부 순서 왜곡(Bias)을 방지하기 위해 **장중 고가(High)·저가(Low)를 참조하지 않습니다.**
- `buy_signal == 1`인 날: **당일 시가(Open) 매수 → 당일 종가(Close) 전량 청산** (오버나이트 불가).
- 구현: `src/v2_execution_engine.py` — `execute_v2_backtest()`

**요구사항(비용)**
- 매수 비용: **0%** (진입 시가 기준 물량 확보 가정)
- 매도 수수료+세금: **`sell_cost = 0.0020` (0.20%)** — `harness.md`·`config/settings.yaml`·엔진 기본값과 동일
- 수익률(거래당):
  - `trade_return = (Close / Open) * (1.0 - sell_cost) - 1.0` (`buy_signal == 1`일 때)
  - `buy_signal == 0`이면 `trade_return = 0.0`

---

### [4단계] 퀀트 메트릭 대시보드 모듈 (Analytics Dashboard)

**목적:** 수집된 모든 매매 로그를 통계화하여 규격화된 템플릿으로 터미널에 출력합니다.

**핵심 지표**
1. 시스템 승률(Win Rate %):  
   - `(수익률 > 0 인 매매 건수 / 총 매매 건수) * 100`
2. 손익비(Profit Factor):  
   - `(총 수익 금액의 합 / 총 손실 금액의 절대값 합)`

**UI 디자인 서식(필수)**
- 아래 `print_dashboard` 템플릿 레이아웃을 **그대로** 맞춥니다.
- 분석과 무관한 디버그 텍스트는 모두 주석 처리 또는 제거합니다.

**표준 출력 템플릿**
```text

=============================================
       📊 SYSTEM v2.0 PERFORMANCE REPORT
=============================================
 • TOTAL TRADES  : {TOTAL} 🚀
 • WIN RATE      : {WIN_RATE:.2f} %
 • PROFIT FACTOR : {PF:.2f}
 • AVG RETURN    : {AVG_RETURN_PCT:.2f} %
---------------------------------------------
{TYPE_COUNTS}
=============================================
```

## 3. 최종 검증 및 인수 조건 (Definition of Done)

1. **사후편향 배제:**  
   - `vol_ratio`는 전일/전전일 거래량(shift) 기준. 진입 판정은 `gap_pct`·`vol_ratio`만 사용.
   - 체결은 당일 Open 진입·당일 Close 청산만 사용(High/Low 미참조).
2. **비용 검증:**  
   - 모든 `trade_return`에 매도 `sell_cost=0.0020` 반영.
3. **가독성 확보:**  
   - `v2_0.quiet_signal_log: true` 시: `loaded tickers` + `pipeline` 요약 1줄 + PERFORMANCE REPORT만 출력.
