## Phase A — 거래 상세 로그 익스포트 (`v4_trades.csv`)

### 목적

자산 소멸 구간을 **거래 단위**로 역추적. “언제, 어떤 종목, 몇 회차, 얼마를 넣고, 청산 후 현금이 얼마인지”를 한 파일에서 확인.

### A-1. 출력 경로

```
outputs/v4_trades.csv
```

(선택) Pass만 모은 로그: `outputs/v4_pass_log.txt` — `portfolio_manager.pass_logs` 기존 필드 활용.

### A-2. CSV 컬럼 설계 (필수)

| 컬럼명 | 타입 | 설명 |
|--------|------|------|
| `trade_id` | int | 청산 1건당 고유 ID (1부터 증가) |
| `side` | str | `BUY` / `SELL` (또는 청산만 `SELL` 1행 + 진입은 별도 BUY 행 — **권장: BUY·SELL 각 1행**) |
| `timestamp` | date | 체결일 (영업일, `YYYY-MM-DD`) |
| `code` | str | 6자리 종목코드 |
| `stage` | int | 1~4 회차 |
| `entry_price` | float | 매수 종가 |
| `exit_price` | float | 청산가 (익절 목표가 또는 타임스탑 종가) |
| `qty` | float | `invest_amount / entry_price` (주 수량, 소수 허용) |
| `invest_amount` | float | 매수 투입 금액 |
| `proceeds` | float | 청산 회수 금액 (`invest_amount * (1 + pnl_rate)`) |
| `pnl_amount` | float | `proceeds - invest_amount` |
| `pnl_rate` | float | 수익률 (비용 반영 후) |
| `exit_type` | str | `익절` / `타임스탑` / `손절` |
| `cash_after` | float | **해당 체결 직후** 현금 잔고 |
| `total_equity_after` | float | **해당 체결 직후** 총자산 (현금 + 포지션 평가) |
| `open_slots_after` | int | 보유 종목 수 (0~3) |
| `slot_budget_at_entry` | float | 진입 당시 `total_equity / max_slots` (감사용) |
| `alloc_ratio` | float | 회차 비중 (0.5/0.3/0.2/0.1) |

**BUY 행 추가 시 (권장):** `side=BUY` 행에 `cash_after`, `total_equity_after`, `slot_budget_at_entry`, `alloc_ratio` 포함.  
**SELL 행:** 위 필드 + `exit_*`, `proceeds`, `pnl_*`.

### A-3. 구현 위치 (예정)

| 파일 | 변경 |
|------|------|
| `src/engine/portfolio_manager.py` | `_process_entries` / `_process_exits`에서 이벤트 누적; `run()` 종료 시 DataFrame 조립 |
| `run_v4_portfolio.py` | `result.trades_detail.to_csv(...)` 호출 |

현재 `trade_rows`에는 `code`, `stage`, `entry/exit_date`, `invest_amount`, `pnl_*`만 있음 → **`cash_after`, `qty`, `slot_budget_at_entry` 등 확장 필요**.

## Phase B — 자산 소멸 집중 감사 (의심 포인트)

Phase A CSV를 기준으로 아래 항목을 **체크리스트 + 스크립트/쿼리**로 검증한다.

### B-1. 포지션 사이징(과대 배분)

**현재 코드 (`portfolio_manager.py`):**

```text
slot_budget = total_equity / max_slots          # max_slots = 3
invest_amount = slot_budget * alloc_ratio       # 1회차 50%, 2회차 30%, ...
```

**감사 항목:**

| # | 검증 내용 | 기대 | 실패 시 의미 |
|---|-----------|------|----------------|
| B-1a | 동일 `timestamp`에 3종목 동시 BUY 시 `sum(invest_amount) <= cash_before` | 항상 참 | 현금 초과 매수 버그 |
| B-1b | `cash_after` 전 구간 `>= 0` | 항상 참 | 마이너스 현금(미수) |
| B-1c | `invest_amount`가 `initial_equity/3*0.5` 등 **고정 초기자본 기준**으로만 계산되지 않는지 | `total_equity` 변동 반영 | 고정 분모 버그 |
| B-1d | 슬롯 3개 × 1회차 50% = 이론상 **최대 150% equity 노출** 가능 여부 | 의도 확인 | 3종목 동시 1회차 진입 시 전액 투입에 가까움 → Ruin 가속 |
| B-1e | `total_equity_after`가 `cash_after + sum(포지션 평가)`와 일치 | 일치 | 평가/Equity 이중계산 |

**산출:** `outputs/v4_audit_sizing.md` (또는 CSV 요약 1페이지) — 위 항목 Pass/Fail 표.

### B-2. 스마트머니 ‘유령’ 진입 (Tracked 만료 부재)

**현재 코드:**

- `scan_smart_money_universe` → `_register_universe`: **기준봉 당일 Top20** 등록
- `TrackedStock`에 `smart_money_date`, `next_entry_day_idx`만 있고 **만료일 없음**
- 이미 tracked인 종목은 `completed`가 아니면 **재등록 스킵** (오래된 추적 유지)

**감사 항목:**

| # | 검증 내용 | 방법 |
|---|-----------|------|
| B-2a | 진입일 − `smart_money_date` 일수 분포 | `v4_trades.csv`에 `days_since_smart_money` 파생 컬럼 추가 후 히스토그램/최대값 |
| B-2b | 30일·60일 이후 진입 건 비율 | 기준봉 후 N일 초과 진입이 손실에 기여하는지 |
| B-2c | `tracked` 누적 개수 일별 시계열 | equity_curve 날짜별 `len(tracked)` 로그 (임시) |

**기대 수정 방향 (Phase D):** 기준봉 후 **N영업일**(예: 20~40) 내 1회차 미충족 시 `tracked` 제거.

### B-3. 단일 엔진 vs 포트폴리오 엔진 로직 불일치

| 구분 | 단일 (`calculate_cascade_backtest`) | 포트폴리오 (`PortfolioManager.run`) |
|------|-------------------------------------|--------------------------------------|
| 루프 | 종목 시계열 1개 while | **전 시장 일자별** for |
| 진입 | `_stage_entry_triggered(df, idx, stage)` | `stage_entry_triggered(hist, stage)` — **누적 hist 마지막 봉** |
| 청산 | `_resolve_exit` — 익일부터 3봉 | `evaluate_daily_exit` — **보유일 hold_days** |
| 회차 | 청산 후 `current_stage += 1`, idx 워프 | 청산 후 `tracked.stage += 1`, `next_entry_day_idx` |
| 자금 | 없음 (비율 PnL만) | **현금·슬롯·slot_budget** |

**감사 항목:**

| # | 검증 내용 |
|---|-----------|

| B-3b | `hold_days` 카운트: 진입 당일 = 0인지 1인지 (단일 엔진은 익일부터 카운트) |
| B-3c | 익절가: 단일은 `entry * 1.035` 터치 시 목표가 청산 — 포트폴리오 동일 여부 |

**산출:** `outputs/v4_logic_diff_066570.md` — 불일치 항목 bullet 목록.
