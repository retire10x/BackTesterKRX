그리고 앞으로 코드를 수정하거나 UI를 개선할 때마다 progress.md를 확인해서 체크리스트를 업데이트하고, 
변경 이력을 맨 위에 누적해서 기록해 줘. 
자, 먼저 progress.md를 읽고 다음 작업을 진행해라."

"다음 프롬프트의 의도를 유지하면서, 토큰 사용량을 최소화하도록 최대한 간결하게 줄여줘. 불필요한 단어, 문장 부호, 설명을 제거해: {질문을 입력}"

이렇게 하면 AI가 컨텍스트를 절대 잃어버리지 않고,

### harness.md
# 🚀 국장 대형주 퀀트 백테스터 프로젝트 규칙 (Harness Core)

## 1. 프로젝트 핵심 메커니즘
- **대상/주기:** 싱글 대형주(`selected_code`) 단일 포지션 몰빵 투자. 일봉 또는 금요 주봉(W-FRI).
- **체결 원칙:** 모든 신호(골든/데드/트레일)는 종가 확정 후 **"다음 봉 시가(Open)"** 체결. 당일 종가 체결 금지.
- **매수 필터:** 골든크로스 발생 시 대세(Slope) + 돌파강도 + 시간버퍼를 **모두 만족(AND)**해야 진입.
- **매도 필터:** 가변 낙폭(트레일링 스탑, 우선순위 높음) 또는 데드크로스 중 하나라도 만족 시 **(OR)** 전량 청산.
- **비용 반영:** 매수 수수료 0.015%, 매도 수수료+세금 0.20%를 백테스트 계산에 엄격히 반영.

## 2. 절대 하지 말 것 (Zero Tolerance)
- **[금지] 시점 왜곡(Look-ahead Bias):** 당일 종가 신호로 당일 시가나 종가에 체결하는 코드 작성 금지.
- **[금지] 오버핏 유도:** 고정된 데이터에만 끼워 맞춘 하드코딩 금지. 파라미터는 `settings.yaml`에서 관리.
- **[금지] 무단 코드 삭제:** 리팩토링 시 기존 시뮬레이터 로직(`simulator.py`)의 누적 수익률, MDD 산출 공식을 임의로 변경하지 말 것.

## 3. 에이전트 행동 지침
- 모든 코드 수정 후에는 `progress.md`에 작업 내용을 기록하고 기능을 체크할 것.
- 가독성이 떨어지는 복잡한 UI 구현 요청 시, 매수/매도 섹션을 분리하는 시각적 그룹화(CSS/Frame)를 최우선 적용할 것.

## 4. progress.md 컨텍스트 과부하 방지 및 청소 루틴
- **비대화 금지:** AI의 혼란 및 메모리 부족을 방지하기 위해 `progress.md` 파일은 항상 최신 맥락 위주로 가볍게 유지한다.
- **아카이브 실행 조건:** 완료된 작업(Done)이 5개 이상 쌓이거나 파일이 100줄을 넘어가면 자동으로 청소를 시작한다.
- **청소 규칙:**
  1. 오래된 디버깅 로그, 에러 메시지 원문, 이미 해결된 구버전 이슈 상세 내역은 `docs/progress_archive.md`로 잘라내어 백업(누적)한다.
  2. 본래의 `progress.md`에는 **[현재 진행 중인 핵심 태스크]**, **[직전 완료된 메인 변경점 2~3개]**, **[최신 아키텍처 상태]**만 명사형 위주로 극도로 압축하여 남긴다.
